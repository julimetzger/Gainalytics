## Priority Areas (Top 5)

### P1 — Video Analysis Suite Is Emulator-Only (Blocks ~30 flows)
All video analysis flows (03–09, ana003–007, gh72, gh130, GH-87) depend on an emulator-specific button **"Import Emulator Squat Video"** or the **"Open"** file-picker dialog (Android emulator sends a simulated video file). These buttons/dialogs are not accessible on a real physical device.
- **Impact:** ~30 flows (48%) can never pass on real device without a real-device import path.
- **Action needed:** Create device-agnostic video import fixtures or skip these on real device.

### P2 — German Text Selectors After EN Translation (#136)
GH-133 translated all UI to English but flow `gh77_dashboard_smoke` still asserts `"Deine Woche auf einen Blick"`. The actual text is now `"Your Week at a Glance"`.
- **Impact:** 1+ flows fail due to translated text.
- **Action needed:** Update text selectors to English equivalents.

### P3 — Stale testID / text selectors (~8 flows)
Several flows use selectors that no longer match the current UI:
- `icon-menu` not found (trn004_r4_feedback_fixes) — testID likely renamed
- `button-text` not found (analyse_date_range_picker) — DateRangePicker button ID changed
- `metrics-muscles-header-0` (11_metrics_overview_slots) — Metrics screen requires exercise selection first; flow has no setup step
- `% VL` (gh82_vl_insight_cards) — flow launches app without navigating to Micro Overview; element only visible on specific screen
- Cardio toast: `"This app can't be used to track cardio"` — the full string is longer; Maestro exact-match fails
- `TestPlanTestPlan` (GH-117) — this plan is not in the standard baseline fixture

### P4 — settings-import-data-button Scroll Intermittency (~4 flows)
`10_trn002`, `gh101`, `gh119`, `gh97_import_warm` fail to scroll to `settings-import-data-button`. The same scroll succeeds in `99_smoke` and `trn005`. The button exists (confirmed via `adb uiautomator dump`, resource-id `settings-import-data-button` at bounds `[9,1248][351,1318]`). Issue is likely timing-sensitive: flows that arrive at Settings mid-navigation may not scroll far enough.

### P5 — gRPC DEADLINE_EXCEEDED on Complex Flows (~13 INFRA-FAILs)
Flows using `clearState: true` (GH-87 suite, 00_import_baseline) and long multi-step flows (trn004, gh130, 08_training_length) hit Maestro internal `java.util.concurrent.TimeoutException` (gRPC deadline). These are Maestro infrastructure timeouts, not app crashes.
- Root causes: `clearState: true` triggers a long app restart + bundle reload; Maestro's 120s gRPC deadline expires before the UI settles.

## Infrastructure Notes

### APK / Metro mismatch on master
The `feature/GH-148` branch (= master HEAD) has `package.json: react-native: 0.82.1` but the project's shared `node_modules` are still at `0.76.9` (npm install not run since #135 upgrade). The Gradle build also failed due to a Kotlin compile error in `react-native-gesture-handler`'s node_modules (cannot infer type for lambda parameter in `FlingGestureHandler.kt`). 

To get a working APK + Metro combination, the GH-139 APK (RN 0.84.1) with the GH-139 Metro (port 8083) was used. GH-139's code is master + RN 0.84.1 upgrade (not yet merged), so this represents a slightly more advanced state than strict master. The flow results should be valid for testing master-era UI code since no UI logic changed in the 0.84.1 upgrade (only native + build configuration).
